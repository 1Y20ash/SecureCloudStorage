# Database Migration Guide

SecureCloudStorage uses **Alembic** for controlled database schema changes.

## Why

Application startup must not silently create or modify database tables. Schema changes are versioned, reviewable, and reproducible through migration revisions.

## First-time setup

Install dependencies:

```bash
pip install -r requirements.txt
```

Run the current schema:

```bash
alembic upgrade head
```

## Creating a future migration

After changing SQLAlchemy models, generate a migration:

```bash
alembic revision --autogenerate -m "describe the schema change"
```

Review the generated file before applying it. Never blindly trust an autogenerated migration.

Apply migrations:

```bash
alembic upgrade head
```

Check current revision:

```bash
alembic current
```

Show migration history:

```bash
alembic history
```

## Existing Phase 1 databases

The initial migration is designed to coexist with databases that already contain the Phase 1 tables created by the former startup bootstrap. Running `alembic upgrade head` records the migration without attempting to recreate tables that already exist.

## Rules

1. Never reintroduce `db.create_all()` into application startup.
2. Never edit an already-applied migration revision.
3. Create a new migration for every schema change.
4. Review migrations manually, especially destructive operations.
5. Test `upgrade` on a clean database and on a representative existing database.
6. Keep migration files in Git.
7. Never put database credentials in migration files.
